
# СМЕНА — концепт-документ

> Браузерная narrative-sim про первую смену оператора контакт-центра банка.  
> Кейс: хакатон банка «Центр-инвест» — игра, погружающая в профессию.  
> Статус: концепт для реализации прототипа (одна полноценная смена).

---

## 1. Elevator pitch

Ты — стажёр на первой смене в контакт-центре регионального банка.  
Слева — живые клиенты (звонки и чаты). Справа — «мозг системы»: CRM, база знаний, скрипты.  
Главная механика — **температура клиента**: баланс скорости, точности и эмпатии.  
За 12–15 минут игрок проживает смену и понимает, чем на самом деле занимается оператор поддержки.

**Слоган:** *Одна смена. Семь клиентов. Ноль права на «просто отключить».*

---

## 2. Цели кейса и как игра их закрывает

| Требование кейса | Как закрываем |
|---|---|
| Браузер, без регистрации | Статика / SPA, никнейм опционален, прогресс в `localStorage` |
| Полноценная глава | Одна смена = 6–7 кейсов + брифинг + дебрифинг |
| Понятная концепция, сюжет, персонажи | Наставник Лена, коллеги, набор клиентов с арками |
| Без критических багов | Узкий scope, детерминированные ветки диалогов |
| Масштабируемость | Кейсы = data-driven JSON; новые смены / отделы = новые пакеты |
| Уникальность | Механика температуры + CRM/БЗ как геймплей, не декорация |
| ★ Сохранение | Автосейв после каждого кейса |
| ★ Сложность | Три режима: Стажёр / Смена / Пик нагрузки |

**Профессия в фокусе:** оператор контакт-центра / специалист поддержки клиентов банка.

**Что игрок узнаёт на практике:**
- скрипты и когда можно от них отойти;
- идентификация клиента и безопасность;
- эскалация и границы полномочий;
- работа с эмоциями и эмпатией под таймером;
- KPI: CSAT, AHT (среднее время), FCR (решение с первого касания), compliance.

## 3. Визуальная идентичность

### 3.1 Настроение
Тёплый «дневной офис» контакт-центра: не корпоративный стерильный синий и не киберпанк.  
Ощущение: «настоящая работа, но играбельно и по-человечески».

### 3.2 Палитра (CSS variables)

```css
:root {
  --bg: #F3F0E8;           /* тёплый фон */
  --bg-deep: #E7E1D4;
  --surface: #FFFDF8;
  --ink: #1C2430;          /* текст */
  --muted: #5C6675;
  --teal: #0F6B6B;         /* бренд / primary */
  --teal-soft: #D7EEEE;
  --accent: #C45C26;       /* CTA / важные акценты (терракота — осторожно, не крем+serif клише) */
  --ok: #2F7D4A;           /* успех / CSAT↑ */
  --warn: #B8860B;         /* растущая температура */
  --hot: #B3261E;          /* критическая температура */
  --line: #D4CFC3;
}
```

**Важно для UI:** без фиолетовых градиентов, без glow, без dark-mode по умолчанию, без «стеклянных» карточек-коллекций в герое.

### 3.3 Типографика
- Display / UI заголовки: **Manrope** или **Unbounded** (выразительный гротеск).
- Текст диалогов и БЗ: **Source Serif 4** или **Literata** — читаемость длинных реплик.
- Моно для CRM/ID: **IBM Plex Mono**.

### 3.4 Визуальный язык интерфейса
Интерфейс = рабочий стол оператора:
1. **Очередь** (слева узкая колонка)
2. **Канал** (центр: звонок / чат)
3. **Инструменты** (справа: CRM + База знаний + Скрипт)
4. **HUD смены** (верх: таймер смены, CSAT, температура текущего клиента, сложность)

Персонажи — stylized flat illustration (2–3 тона + контур), не фотореализм.

## 4. Сторилайн прототипа

### Акт 0 — Меню
Никнейм (опционально) → «Начать смену».

### Акт 1 — Брифинг (1–2 мин)
Наставник **Лена** (тимлид):
> «Сегодня ты не один. Я на линии. Не геройствуй: если не уверен — эскалируй.  
> Главное не скорость любой ценой, а чтобы человек ушёл спокойнее, чем пришёл.»

Цели смены (UI-чеклист):
1. Закрыть минимум 5 обращений  
2. Удержать средний CSAT ≥ 3.5 / 5  
3. Не допустить 2+ критических ошибок compliance  

### Акт 2 — Смена (ядро, 10–12 мин)
6 обязательных кейсов + 1 опциональный «входящий в пике».  
Между кейсами — короткие реплики Лены / коллеги из чата «Курилка» (атмосфера, лёгкий юмор, подсказки без спойлеров).

### Акт 3 — Дебрифинг
Разбор смены: что сработало, где срезало compliance, чему учит профессия.  
Карточка результата + разблокировка «дневника оператора» (лор для расширения).

## 6. Геймплей и уникальные механики

### 6.1 Температура клиента (core loop)

Шкала **0–100**:
- `0–30` холодный / спокойный  
- `31–60` тёплый / напряжённый  
- `61–85` горячий  
- `86–100` кипяток → риск срыва (форс-завершение с низким CSAT) / эскалация обязательна  

**Что поднимает температуру**
- долгий ответ без действия;
- шаблонная фраза «по скрипту», когда человек уже объяснял;
- неверная идентификация;
- обещание вне полномочий;
- игнор эмоции («просто ответьте по факту» в момент паники).

**Что снижает**
- признание эмоции + конкретика следующего шага;
- быстрый поиск в БЗ и опора на факт;
- прозрачность сроков («сейчас проверю 20 сек»);
- корректная эскалация с объяснением.

Температура влияет на:
- доступные реплики (часть «мягких» пропадает на кипятке);
- скорость деградации таймера;
- финальный CSAT кейса.

### 6.2 Три столпа действия (каждый ход)

На каждом шаге диалога игрок выбирает **комбо**:

1. **Реплика** (3–4 варианта: эмпатия / факт / скрипт / давление-ускорение)  
2. **Инструмент** (опционально до ответа):  
   - открыть карточку CRM  
   - найти статью в Базе знаний  
   - запустить проверку операции  
   - эскалировать  
3. **Время** — скрытый ресурс: чем дольше думаешь/ищешь, тем выше температура (на сложности «Пик» — жёстче)

Правильный ответ ≠ всегда «самая добрая фраза».  
Иногда нужна жёсткая проверка личности. Иногда — быстрый FCR без воды.

### 6.3 CRM как геймплей
Карточка клиента содержит:
- ФИО / статус / продукты  
- последние операции  
- флаги риска (подозрение фрода, VIP, жалобщик)  
- заметки прошлых операторов  

Игрок должен **сверять** слова клиента с CRM.  
Рассинхрон = квест (мошенничество / путаница счёта / ошибка клиента).

### 6.4 База знаний
Поиск по тегам: `комиссии`, `переводы`, `фрод`, `закрытие карты`, `юрлица`.  
Статья даёт:
- короткий алгоритм;
- «можно / нельзя»;
- фразу-шаблон (использовать или адаптировать).

**Уникальность:** статья не автопобеда. Если процитировать шаблон в лицо разъярённому клиенту — температура растёт.

### 6.5 Compliance-ловушки
Скрытые правила (открываются через БЗ/Лену):
- не называть полный номер карты;
- не обходить идентификацию «по просьбе»;
- не обещать возврат без основания;
- при признаках фрода — стоп-скрипт и перевод.

Критическая ошибка compliance = сильный штраф в дебрифинге, даже при высоком CSAT.

### 6.6 KPI смены (прозрачный HUD)

| Метрика | Как считается | Зачем в игре |
|---|---|---|
| CSAT | среднее по кейсам (1–5) | эмпатия + результат |
| AHT | среднее время кейса | скорость |
| FCR | % решённых без эскалации | компетенция L1 |
| Compliance | 100% минус штрафы | безопасность |
| Stress | скрытый ресурс игрока | antifire / обучение границам |

Итог смены — не один «score», а **профиль оператора** (скоростной / заботливый / осторожный), чтобы показать многогранность профессии.

## 7. Структура одного кейса (шаблон)

```text
1. Incoming (превью в очереди: канал, приоритет, тег)
2. Connect (идентификация / отказ от болтовни)
3. Problem framing (клиент формулирует)
4. Investigate (CRM + БЗ + вопросы)
5. Resolve / Escalate
6. Soft close (финальная реплика)
7. Aftermath (CSAT + комментарий Лены + лор-заметка)
```

Каждый кейс: 4–6 узлов диалога, 2–3 «правильных» ветки разного стиля, 1–2 провальные.

## 8. Кейсы прототипа (дизайн детально)

### C1 — «Комиссия» (туториал механик)
- Учит: CRM + БЗ + температура  
- Правильный путь: найти операцию → объяснить тариф → предложить вариант оспаривания / эскалацию  
- Ловушка: сразу пообещать возврат  

### C2 — «Перевод не уходит»
- Учит: диагностика (лимиты, статус карты, техработы)  
- Ловушка: советовать «просто переустановите приложение» без проверки  

### C3 — «Звонили из банка» (фрод)
- Учит: стоп-скрипт безопасности  
- Правильный путь: не запрашивать коды, проверить признаки, успокоить, зафиксировать инцидент  
- Ловушка: попросить «назвать код из смс для проверки»  

### C4 — «Закрыть карту»
- Учит: полномочия L1, удержание vs токсичное удержание  
- Правильный путь: уточнить причину, предложить альтернативу 1 раз, если настаивает — корректная процедура / эскалация  

### C5 — «Платёж юрлица»
- Учит: другой тип клиента, реквизиты, статусы платежа, эскалация на платежный стол  
- Ловушка: говорить уверенно без проверки в CRM  

### C6 — «Жалоба на оператора»
- Учит: работа с эмоцией, не защищать «своих» вслух, фиксация претензии  
- Клиент горячий с старта — стресс-тест температуры  

### C7★ — «Не тот продукт»
- Учит: внимательность, когда клиент «не ваш» / ошибка маршрутизации  
- Награда за корректный перевод без натягивания решения

## 9. Сложности (★)

| Режим | Таймер ответа | Старт температуры | Подсказки Лены | Compliance |
|---|---|---|---|---|
| Стажёр | мягкий | −10 к старту | частые | мягкие штрафы |

## 13. Учебный эффект (для презентации жюри)

После смены экран «Что делает оператор на самом деле»:
- слушает и структурирует проблему;
- проверяет факты в системах;
- соблюдает безопасность;
- управляет эмоцией — своей и клиента;
- понимает границу L1 / L2;
- работает на прозрачные метрики, а не на «угадай ответ».

Фраза для слайда:
> Мы не симулируем «красивый колл-центр из рекламы».  
> Мы даём почувствовать ответственность первой линии.

## 15. Технический стек (предложение под прототип)

| Слой | Выбор | Почему |
|---|---|---|
| UI | React + Vite + TypeScript | быстрый браузерный прототип, удобные панели |
| Стили | CSS modules / vanilla CSS variables | полный контроль атмосферы |
| Контент кейсов | JSON / TS modules | дизайнеры могут расширять без кода логики |
| Диалоговый раннер | свой легкий state-machine | предсказуемость, без оверкилла RPG-движка |
| Ауты | Howler или HTML Audio (минимум) | рингтон / UI tick |
| Сейвы | localStorage | ★ требование |
| Деплой | GitHub Pages / Cloudflare Pages | QR на презентацию |
| Аналитика | опционально, без ПДн | только анонимные события сессии |

**Не берём Unity WebGL** — дольше грузится, хуже для «открыл страницу — играешь» (критерий кейса).

## 17. Метрики успеха демо (внутренние)

Сессия считается «полноценной», если игрок:
1. прошёл брифинг;
2. завершил ≥ 5 кейсов **или** дошёл до конца смены;
3. увидел дебрифинг с разбором профессии;
4. без краша и без тупика без UI-выхода.

Целевая длина демо: **12–18 минут**.

## 18. Риски и контрмеры

| Риск | Контрмера |
|---|---|
| «Слишком текстовая» | жёсткий лимит реплик, визуальный HUD, температура как action |
| «Не про профессию, а про угадайку» | несколько валидных стилей решения + дебрифинг «почему» |
| Чувствительность темы мошенничества | аккуратный тон, без инструкций «как обмануть», только защита клиента |
| Перегруз UI | progressive disclosure: CRM/БЗ открываются по туториалу |
| Не успеем контент | data-driven кейсы; режем C7 и часть реплик, не режем core loop |
